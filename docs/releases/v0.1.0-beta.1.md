# v0.1.0-beta.1 — first beta

This is the first **beta prerelease** of dunst_tray, not a stable release.
Runtime/Python package version: **0.1.0b1**. Please report reproducible issues
with synthetic examples, never private notification history or real messages.

## A lightweight companion for Dunst

Keep Dunst's popups and add a persistent grouped notification center and an
Xfce/XEmbed tray bell with one white dot for unread notifications.

- Review retained notifications, expand application groups and show older items.
- Use **Show app** without requiring an original notification callback. Exact
  window identities and conservative terminal ownership checks prevent guessing
  between unknown or ambiguous windows.
- Repeatedly **Open discussion** with compatible Walite v2 builds through
  private, rotating one-use tickets; drafts and dialogs remain protected.
- Configure opacity, dimensions, corner radius and application icons.
- Optionally hide the center after inactivity: off by default, initially five
  seconds, adjustable from 3–120. Interaction and Settings pause/reset the timer.
- Keep notification history, unread state and DND independent of window hiding.

## Requirements and known limitations

Linux/X11, Python 3.11+, GTK3/PyGObject/Pycairo, Dunst/dunstctl, wmctrl, xprop and
an XEmbed tray. Verified on MX Linux / Debian Trixie / Xfce with Dunst 1.12.2.
The existing user installer preserves preferences/history and leaves Dunst alone.

The session bus must permit passive notification monitoring. An X11 compositor
is needed for transparency/rounded clipping; otherwise the panel is rectangular
and opaque. Popups and their positioning remain Dunst's responsibility.

- Wayland is unsupported; i3 integration is not yet verified.
- Show app raises an existing verified window, not a particular message. It
  never starts a new client; ambiguous terminals/windows remain unavailable.
- aerc's current notification hook has no safe retained email target. Generic
  focusing works; opening a specific email is not implemented.
- Repeated Walite discussion navigation requires the coordinated v2 producer
  (`5ad0b96` or a compatible descendant), not simply any v1.2.1 installation.
  Tickets expire at their original deadline and do not survive a Walite restart.
- Notification contents remain private local data, not release/package assets.
- Light-panel configuration, compositor-off operation, monitor hotplug,
  session-bus disconnection and long-duration resource use remain unverified.
- Reboot/autostart success on Xfce is user-reported, not an agent-run reboot test.

## Download, verify and install

Download both curated assets from this prerelease into the same folder:

- [dunst-tray-0.1.0-beta.1.tar.gz](https://github.com/antoinebaudrimont-beep/dunst_tray/releases/download/v0.1.0-beta.1/dunst-tray-0.1.0-beta.1.tar.gz)
- [SHA256SUMS](https://github.com/antoinebaudrimont-beep/dunst_tray/releases/download/v0.1.0-beta.1/SHA256SUMS)

```sh
sha256sum -c SHA256SUMS
tar -xzf dunst-tray-0.1.0-beta.1.tar.gz
cd dunst-tray-0.1.0-beta.1
sudo apt install dunst python3 python3-gi python3-cairo \
  python3-gi-cairo gir1.2-gtk-3.0 wmctrl x11-utils
./scripts/install.sh
~/.local/bin/dunst-tray --version
~/.local/bin/dunst-tray
```

Run the installer as your normal user, **not sudo**. Dependencies are the only
system packages above. Dunst must already be running in your session; the
installer neither replaces nor reconfigures it. Checksum verification detects
corruption but is not a digital signature. The curated archive is distinct
from GitHub's automatic “Source code” downloads.

To upgrade an existing installation, quit the tray, keep the old source archive
for rollback, and run the new installer before restarting the tray. Existing
preferences, history and unread state are retained; auto-hide remains disabled
unless you enable it. The beta makes no schema change from `4cd15f4`; rollback
to that version uses its installer, again with the tray stopped. Do not remove
your data or run purge to upgrade/roll back.

`./scripts/uninstall.sh` removes the app/autostart but keeps preferences/history.
`./scripts/uninstall.sh --purge` also permanently removes that private data.
Neither removes Dunst. Keep the extracted source to use its removal script.

## Validation and packaging

- Full automated suite: **79 tests**, including **17 opt-in GTK/X11 tests**;
  headless CI runs **62 tests and skips 17**, on Python **3.11 and 3.13**.
- All three screenshots are real native GTK3/X11 captures, individually reviewed
  with metadata/integrity guards. Only fictional notifications were loaded.
- Source archive rebuilt twice byte-for-byte with SHA-256 verification;
  contains source, installer/removal scripts, assets, tests, docs/screenshots
  and the **MIT license**, but no user databases, settings or credentials.
- Installation, upgrade from the previously published `4cd15f4`, state/unread
  preservation, uninstall, reinstall and purge are validated in a disposable
  filesystem/PID/network sandbox. No installed personal application is changed,
  stopped or restarted. Walite is not modified or bundled.
- Existing Xfce/X11 live acceptance covers grouping/history, DND, settings,
  generic app focus, repeatable Walite v2 navigation and inactivity auto-hide.
  This release preparation does not repeat private-message or reboot tests.
- GTK3 StatusIcon deprecation warnings are known; an XEmbed tray is required.
