## A lightweight companion for Dunst

Keep Dunst's popups and add a persistent grouped notification center and an
Xfce/XEmbed tray bell with one white dot for unread notifications.

- Review retained notifications, expand application groups and show older items.
- Use **Show app** without requiring an original notification callback. Exact
  window identities and conservative terminal ownership checks prevent guessing
  between unknown or ambiguous windows.
- Repeatedly **Open discussion** with compatible Walite v2 builds through
  private, rotating one-use tickets; drafts and dialogs remain protected.
- Configure opacity, dimensions, corner radius and application icons.
- Optionally hide the center after inactivity: off by default, initially five
  seconds, adjustable from 3–120. Interaction and Settings pause/reset the timer.
- Keep notification history, unread state and DND independent of window hiding.

## Requirements and known limitations

Linux/X11, Python 3.11+, GTK3/PyGObject/Pycairo, Dunst/dunstctl, wmctrl, xprop and
an XEmbed tray. Verified on MX Linux / Debian Trixie / Xfce with Dunst 1.12.2.
The existing user installer preserves preferences/history and leaves Dunst alone.

- Wayland is unsupported; i3 integration is not yet verified.
- Show app raises an existing verified window, not a particular message. It
  never starts a new client; ambiguous terminals/windows remain unavailable.
- aerc's current notification hook has no safe retained email target. Generic
  focusing works; opening a specific email is not implemented.
- Repeated Walite discussion navigation requires the coordinated v2 producer
  (`5ad0b96` or a compatible descendant), not simply any v1.2.1 installation.
  Tickets expire at their original deadline and do not survive a Walite restart.
- Notification contents remain private local data, not release/package assets.
